# Exploring Your Data

With a connection selected, you get a two-panel layout — a sidebar of tables on the left, a data grid on the right. Connections come from the [Connector](/connector/install) and are available here automatically.

---

## The sidebar

With a connection active, the left sidebar displays all discoverable database schemas and tables.

![Data Explorer Left Sidebar showing schema selector, table search filter, and table list with live row counts](/images/de/de-grid/tables.png)

- **Schema selector** — Switch between any schema in your database (`public`, `analytics`, `audit`, `inventory`, `staging`, etc.), defaulting to `public`. Switching schemas dynamically reloads the table list.
- **Searchable table list** — Filter tables with the `Filter tables...` search input, which displays a live count badge (e.g. `59` tables).
- **Row counts & indicators** — Each table item shows an estimated row count badge (e.g., `admin_chat 2.2K`, `ai_token_logs 31.0K`) so you can gauge size at a glance.
- **Collapsible sidebar** — Click the collapse toggle icon in the top right of the sidebar header to hide the sidebar and give your data grid maximum horizontal screen space.

## Smart column sizing

Columns size themselves to fit your actual data, measured with the browser's canvas text renderer so the widths match what you see.

### How it works

1. **Measured, not guessed** — text widths are measured using the same font the cell renders in
2. **Sampled from real rows** — the first 8 rows of the current page are measured and the **widest** value sets the column width
3. **A minimum applies to every column** — a column is never narrower than its header needs, with a 100px floor so key and type labels always fit
4. **A maximum applies by type**, so a long text value can't push a numeric column out of shape:

| Column type | Maximum width |
|---|---|
| Boolean | 110px |
| Integer, numeric, float | 160px |
| Date, time, timestamp | 200px |
| UUID | 280px |
| Text and everything else | 450px |

### Changing a width

Drag the right edge of a header to resize, or **double-click the edge to reset** it to the calculated width.

Widths you set are remembered per connection, schema, and table, so a table you tuned stays tuned. Writes are debounced while you drag, and the most recently used 50 table layouts are kept.

## Sorting

Click the sort control on any column header to cycle:

1. **Ascending**
2. **Descending**
3. **Off** — back to the default order

Sorting runs in the database, so it stays fast on large tables. Changing the sort returns you to the first page.

## Filtering

Click **Filter** in the grid toolbar to open the filter popover.

![Add Filter dialog in Schema Weaver Data Explorer with Instant In-Memory mode and Query entire database option](/images/de/de-grid/fillter.png)

### Dual-mode filtering

Schema Weaver supports two complementary filtering strategies:

1. **Instant In-Memory Filtering (Default)**
   - Indicated by the green **`Instant In-Memory`** badge in the popover header.
   - Evaluates filter conditions instantaneously on the client side across all rows currently loaded in your browser memory (e.g., your active 500, 1k, or 2k rows).
   - Provides instant, zero-latency typing feedback with no roundtrip database latency — ideal for rapid exploratory analysis on the loaded page.

2. **Query Entire Database**
   - Check the **Query entire database** checkbox.
   - Translates your condition into a server-side SQL `WHERE` clause and executes it against the live PostgreSQL database through your connector.
   - Scans the entire table (even across millions of rows), fetching and displaying matching records regardless of whether they were in your initial page memory.

### Supported operators

| Column type | Operators |
|---|---|
| **Text** | `~ Contains`, `Does not contain`, `Starts with`, `Ends with`, `Is empty`, `=`, `≠` |
| **Number** | `=`, `≠`, `>`, `≥`, `<`, `≤` |
| **Boolean** | `=`, `≠` |
| **Date / time** | `=`, `≠`, `>`, `≥`, `<`, `≤` |
| **Any type** | `In list`, `Is null`, `Not null` |

Active filters appear as dismissible chips in the action bar. Remove any single filter by clicking its **✕** button, or click **Clear all** to reset the view.

## Columns

The **Columns** button allows you to control which fields appear in your grid view.

![Columns popover in Schema Weaver Data Explorer showing search bar, column list with data types, and Hide except PK shortcut](/images/de/de-grid/columns-fillter.png)

- **Visibility counter** — The button label dynamically tracks your active column ratio (e.g. `Columns (12 / 12 visible)`).
- **Column search** — Quickly filter through wide tables using the `Search columns...` search box.
- **Data type indicators** — Lists PostgreSQL data types alongside each column name (`integer`, `character varying(50)`, `text`, `text[]`, etc.).
- **Convenient presets**:
  - **Show all**: Instantly restores visibility for all columns.
  - **Hide except PK**: One-click action to hide every column except the primary key (`id`), giving you a clean baseline to add back only the specific fields you need.
- **Persistent preferences**: Your visibility choices are stored per connection, schema, and table so your customized layouts remain intact when you return.

## Column statistics

Click a **column header** — not the sort control — to open the stats panel for that column.

| Stat | What it shows |
|---|---|
| **Type** | Full data type, with a nullable marker |
| **Flags** | Primary key and indexed badges |
| **Null %** | How much of the column is empty |
| **Distinct count** | How many unique values |
| **Min / max** | Range, for numbers and dates |
| **Completeness** | A bar showing the non-null share |
| **Top values** | Most frequent values with their share |
| **Sample values** | A quick look at real values |

Close it with the X, or by clicking the same header again.

## Click to copy

Click any cell to copy its value directly. A brief **Copied** badge confirms the action.

| Cell value | Copied as |
|---|---|
| `NULL` | `NULL` |
| Boolean | `true` or `false` |
| JSON | Pretty-printed |
| Date | ISO 8601 |
| Text | As shown |

## Cell hover preview & inspector

Long strings, multi-sentence messages, JSON structures, and arrays are truncated with an ellipsis (`...`) in the grid to maintain compact row heights. Rather than requiring you to expand columns, drag headers, or open a separate modal, Schema Weaver includes an **instant cell hover preview**:

![Cell hover preview popover in Schema Weaver Data Explorer showing complete unclipped text content, character count, and full inspector shortcut](/images/de/de-grid/hover-full-message.png)

### Key capabilities:

- **Instant zero-click inspection**: Hover over any truncated cell in any column to immediately read the complete, unclipped text.
- **Context details**: The popover header shows the target column name (e.g. `message`), data type badge (`text`), and row reference (`Row #7`).
- **Quick actions**:
  - **Copy**: Copy the complete unclipped text to your clipboard with a single click.
  - **Expand**: Enlarge the floating card for lengthy paragraphs or complex documents.
  - **Full inspector**: Jump to the comprehensive cell inspector modal for nested JSON tree inspection or multi-line formatting.
- **Character count**: Displays the exact length of the cell value (e.g., `276 chars`).
- **Keyboard friendly**: Press `Esc` anytime to instantly dismiss the preview card.

## Pagination & page fetch limits

The grid uses high-performance cursor pagination to seamlessly page through massive PostgreSQL tables. You can customize how many rows are fetched into memory per page using the **Rows per page** selector in the grid toolbar:

![Page size selector dropdown in Schema Weaver Data Explorer showing 100, 250, 500, 1000, and 2000 rows per page options](/images/de/de-grid/page.png)

### Rows per page options:

- **100 / page** — Minimal memory footprint for mobile or slower connections
- **250 / page** — Standard responsive scrolling
- **500 / page** (Default) — Recommended sweet spot for performance and in-memory exploration
- **1000 / page (1k)** — Broader working set for batch review
- **2000 / page (2k)** — Maximum batch fetch for deep client-side in-memory filtering across thousands of rows

The bottom status bar displays your current position alongside an estimated total row count (e.g. `Showing 500 of ~2.0K rows`). Because paging is cursor-based, moving forward through millions of rows stays instantaneous.
